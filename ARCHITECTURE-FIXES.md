## Детали каждой правки

### 1. Таблица `trucks`

**Проблема:** Грузовик привязан к водителю через текстовое поле `users.truckNumber`. В реальности водители меняют грузовики, пробег и техобслуживание должны отслеживаться по машине, а не по человеку.

**Что сделать:**
- Добавить таблицу `trucks` в [src/db/schema.ts](src/db/schema.ts):
  ```ts
  export const trucks = sqliteTable("trucks", {
    id: integer("id").primaryKey({ autoIncrement: true }),
    number: text("number").notNull().unique(),
    make: text("make"),
    model: text("model"),
    year: integer("year"),
    vin: text("vin"),
    isActive: integer("is_active", { mode: "boolean" }).notNull().default(true),
    createdAt: text("created_at").notNull().default("(datetime('now'))"),
  });
  ```
- Добавить `truckId` в таблицу `trips` (вместо/рядом с текущим `truckNumber` на users)
- Убрать `truckNumber` из таблицы `users`
- Обновить API `/api/trips` и страницы owner

### 2. Multi-tenancy — таблица `companies`

**Проблема:** Нет изоляции данных между разными компаниями. Все пользователи и данные в одной общей БД — невозможно запустить как SaaS для нескольких клиентов.

**Что сделать:**
- Добавить таблицу `companies`:
  ```ts
  export const companies = sqliteTable("companies", {
    id: integer("id").primaryKey({ autoIncrement: true }),
    name: text("name").notNull(),
    slug: text("slug").notNull().unique(),
    createdAt: text("created_at").notNull().default("(datetime('now'))"),
  });
  ```
- Добавить `companyId` в таблицы: `users`, `trucks`, `trips`, `expenses`
- В каждом API-запросе фильтровать по `companyId` из сессии
- Добавить в `SessionData` поле `companyId`

---

### 3. GPS трекинг в фоне

**Проблема:** `navigator.geolocation.watchPosition()` перестаёт работать когда телефон гасит экран или водитель переключается в другое приложение. Данные GPS пропадают на большей части маршрута.

**Варианты решения (выбрать один):**

**Вариант A — PWA + Service Worker (проще, в рамках текущего стека):**
- Добавить Service Worker который периодически будит браузер
- Ограничение: не все браузеры поддерживают фоновую геолокацию

**Вариант B — Нативное мобильное приложение (правильно для продакшена):**
- React Native или Expo поверх того же API
- GPS работает корректно в фоне
- Рекомендуется для финального продукта

**Вариант C — GPS-трекер на машине (без телефона):**
- Аппаратный трекер (GL300, Teltonika и др.) пингует сервер напрямую
- Самый надёжный вариант для коммерческого транспорта

**Краткосрочная правка (пока без нативного приложения):**
- Добавить предупреждение водителю: "Не гасите экран во время поездки"
- Изменить интервал трекинга с watchPosition на setInterval + getCurrentPosition каждые 30 сек
- Добавить Wake Lock API чтобы экран не гас

### 4. Хранение файлов в облаке

**Проблема:** Папка `uploads/` существует только на локальной машине. На Vercel, Railway, любом облачном деплое — файлы пропадают при перезапуске.

**Что сделать:**
- Подключить Cloudflare R2 (дешевле S3, есть бесплатный tier) или AWS S3
- Установить `@aws-sdk/client-s3` или Cloudflare R2 SDK
- Изменить функцию в [src/lib/upload.ts](src/lib/upload.ts) — вместо записи на диск загружать в облако
- Хранить в БД URL файла вместо локального пути
- Переменные окружения: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`

---

### 5. База данных — один файл и PostgreSQL для продакшена

**Проблема:** Три файла БД (`notc.db`, `audit.db`, `local.db`) — признак отсутствия порядка. SQLite не поддерживает конкурентные запись от нескольких процессов/серверов.

**Что сделать:**
- Объединить всё в один файл `notc.db` — проверить что `audit.db` и `local.db` не используются активно
- Для продакшена — мигрировать на PostgreSQL (Neon, Supabase, Railway — есть бесплатные варианты)
- Drizzle ORM поддерживает PostgreSQL без изменения кода схемы — только поменять адаптер в [src/lib/db.ts](src/lib/db.ts)

---

### 6. SESSION_SECRET без fallback

**Проблема:** Если не задана переменная `SESSION_SECRET` — приложение использует захардкоженный секрет. В продакшене это дыра в безопасности.

**Что сделать** в [src/lib/auth.ts](src/lib/auth.ts):
```ts
// Было:
password: process.env.SESSION_SECRET || "this-is-a-dev-secret-...",

// Стало:
const secret = process.env.SESSION_SECRET;
if (!secret) throw new Error("SESSION_SECRET env var is required");
const sessionOptions: SessionOptions = {
  password: secret,
  ...
};
```

### 7. SMS-оповещения владельцу

**Зачем:** Мгновенное уведомление когда водитель добавляет чек — особенно если сумма или расход выглядят подозрительно.

**Что сделать:**
- Подключить [Twilio](https://twilio.com) или [Vonage](https://vonage.com) (оба дают бесплатный trial на старт)
- Альтернатива без оплаты: **Telegram Bot** — владелец получает сообщение в Telegram (полностью бесплатно)
- Триггеры для оповещений:
  - Водитель добавил чек (сумма + фото)
  - Расход топлива выбился из нормы (например, >1.5x от среднего)
  - Поездка завершена (итог км + расходы)
- Добавить `ownerPhone` или `ownerTelegram` в таблицу `companies`
- Логику отправки — в `src/lib/notifications.ts`

**Рекомендуется начать с Telegram Bot** — нулевая стоимость, легко настроить, не нужна верификация номера.
